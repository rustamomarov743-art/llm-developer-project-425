Проверка — финальное ревью

Финальный шаг: убедитесь, что проект работает целиком, и подготовьте его к сдаче. Полный список того, как проверяется проект, требований к оформлению и пунктов для самопроверки — в чек-листе проекта.
Что сдавать

    Репозиторий на GitHub с конфигами решения: src/workflow.yaml, .env.example, README.md и исходники поллера и MCP-функции в src/ — на выбранном вами языке.
    Работающий почтовый агент — адрес Help Desk-ящика для проверяющего.
    README.md с разделом «что попробовать» — 3–4 готовых промпта для проверяющего.

Что вы должны уметь объяснить

    Какой секрет куда положен (YDB_ENDPOINT, YDB_DATABASE, email-credentials с app-password — в Lockbox) и какие роли у сервисного аккаунта.
    Почему pull-архитектура (CF по таймеру забирает почту через IMAP), а не входящий webhook.
    Почему MCP реализован через Cloud Function, а не через внешний remote.
    Почему Responses API, а не Assistant API (устарел).
